# iPad 11 리빌드

Apple Korea의 iPad 제품 페이지를 참고해 만든 개인 프론트엔드 리빌드 프로젝트입니다.

단순히 화면을 비슷하게 따라 만드는 것보다, 제품 소개 페이지의 정보 흐름을 분석하고 첫 화면 모션, 헤더 패널, 제품 내비게이션, 비교 섹션, 접근성 흐름을 직접 구현하는 데 집중했습니다.

<a id="why-built"></a>

## 만든 이유

이 프로젝트는 공식 페이지를 그대로 복제하기보다, 신입 프론트엔드 개발자 관점에서 구현 가능한 범위를 정하고 다시 설계한 프로젝트입니다.

공식 페이지의 시각 흐름과 정보 구조를 참고하되, HTML, CSS, JavaScript만으로 직접 구현 가능한 구조로 재해석했습니다.

중점적으로 본 부분은 다음과 같습니다.

- 제품 소개 페이지의 섹션 흐름 정리
- 헤더, 검색, 장바구니, 모바일 메뉴처럼 상태가 있는 화면 구현
- 반응형, 접근성, 문서화, 배포 전 검수 흐름 정리

## 주요 구현 내용

<a id="feature-01"></a>

### 1. 첫 화면 모션

첫 화면에서 제품이 자연스럽게 인식되도록 구성했습니다.

- iPad 로고 분리 애니메이션 구현
- 문구, 가격, 버튼이 순차적으로 보이도록 구성
- 화면 크기별 문구 간격과 이미지 밀도 조정
- 과한 효과보다 제품 소개 흐름이 잘 보이도록 정리

<br />

<a id="feature-02"></a>

### 2. 헤더 패널 구현

검색, 장바구니, 모바일 메뉴처럼 상태가 필요한 화면을 JavaScript로 직접 제어했습니다.

- 검색 패널 열림과 닫힘 구현
- 장바구니 패널 열림과 닫힘 구현
- 모바일 메뉴 열림과 닫힘 구현
- ESC, 외부 클릭, 스크롤 상황에서 닫힘 흐름 정리
- 열린 패널과 닫힌 패널의 접근성 상태 관리

<br />

<a id="feature-03"></a>

### 3. 접근성 흐름 보완

마우스뿐 아니라 키보드로도 화면을 탐색할 수 있도록 포커스 흐름을 점검했습니다.

- 패널이 열릴 때 내부 요소로 포커스 이동
- 패널이 닫힐 때 기존 버튼으로 포커스 복귀
- 키보드 탐색 순서 점검
- 포커스가 보이도록 스타일 보완
- 모바일 메뉴, 검색, 장바구니의 탭 이동 흐름 정리

<br />

<a id="feature-04"></a>

### 4. 데이터 기반 비교 섹션

비교 섹션은 같은 구조의 HTML을 반복 작성하지 않고, 데이터를 기준으로 화면을 생성했습니다.

- `data/ipads.js`에 제품 정보 분리
- 제품명, 이미지, 색상, 가격, 버튼 정보를 데이터로 관리
- JavaScript로 비교 카드 렌더링
- 제품 정보 수정 시 데이터만 고치면 반영되도록 구성

<br />

<a id="feature-05"></a>

### 5. 스타일 파일 구조 정리

하나의 CSS 파일에 모여 있던 스타일을 역할별로 나누어 관리했습니다.

- `main.css`: 전체 화면과 주요 섹션 스타일
- `header.css`: 헤더, 검색, 장바구니, 모바일 메뉴 스타일
- `footer.css`: 푸터, 안내 문구, 각주 영역 스타일
- 수정할 위치를 찾기 쉽게 정리
- 스타일 충돌 가능성 감소

<br />

<a id="feature-06"></a>

### 6. 안내 문구와 각주 정리

제품 소개 페이지 하단의 안내 문구와 각주 흐름도 함께 정리했습니다.

- 본문 각주 링크와 하단 안내 문구 연결
- 각주 클릭 시 해당 내용 강조
- 주소 해시 초기화 처리
- 일반 문장과 강조 문장의 시각 위계 정리

<a id="focus-point"></a>

## 중점적으로 보여주고 싶은 부분

이 프로젝트에서 가장 중요하게 본 것은 “얼마나 똑같이 만들었는가”가 아니라 “왜 이렇게 구현했는가”입니다.

특히 다음 기준을 중심으로 작업했습니다.

- 공식 페이지에서 참고할 부분과 제외할 부분을 구분했는가
- 정적 페이지에서 상태가 있는 화면을 어떻게 관리했는가
- 헤더, 패널, 비교 카드, 각주처럼 성격이 다른 기능을 어떻게 나누었는가
- 반응형과 접근성을 구조 안에 함께 반영했는가
- 개선 전과 개선 후를 비교할 수 있는가

<a id="development-flow"></a>

## 개발 흐름

이 프로젝트는 결과물만 남기지 않고, 개선 전후를 비교할 수 있도록 브랜치를 나누어 관리했습니다.

| 브랜치 | 역할 |
|---|---|
| `main` | 이전 버전 기록 |
| `dev` | 기능 개발, 구조 개선, 문서화 기준 |
| `release/1.0.0` | 배포 전 검수 |
| `master` | 현재 배포 기준 |

현재 배포 흐름은 다음과 같습니다.

    dev
    └─ release/1.0.0
       └─ master
          └─ Netlify 배포

`main`을 덮어쓰지 않고 남겨둔 이유는, 개선 전과 개선 후를 비교할 수 있는 기록으로 활용하기 위해서입니다.

<a id="ai-workflow"></a>

## 인공지능 활용 방식

이 프로젝트에서는 인공지능을 단순 코드 생성 도구로 사용하지 않고, 개발 판단을 정리하고 검수 범위를 넓히는 보조 도구로 활용했습니다.

| 활용 영역 | 활용 방식 |
|---|---|
| 구현 방향 정리 | 헤더 패널, 모바일 메뉴, 비교 섹션의 구조 검토 |
| 리팩토링 범위 설정 | CSS와 JavaScript 파일 분리 기준 정리 |
| 접근성 점검 | 포커스 복귀, 키보드 탐색, 접근성 상태 점검 |
| 검수 항목 정리 | 데스크탑, 태블릿, 모바일 확인 항목 정리 |
| 문서화 보조 | 작업 기록, 정책 문서, 배포 기록 문장 정리 |
| 디버깅 관점 확장 | 패널 잔상, 포커스 흐름, 반응형 문제 원인 분해 |

인공지능이 제안한 내용을 그대로 적용하지 않고, 현재 프로젝트 구조와 구현 수준에 맞는지 확인한 뒤 필요한 부분만 선택적으로 반영했습니다.

이를 통해 문제를 정의하고, 구현 범위를 조정하고, 검수 기준을 문서화하는 개발 흐름을 연습했습니다.

<a id="retrospective"></a>

## 회고

이 프로젝트를 통해 단순히 화면을 만드는 것보다, 실제 제품 소개 페이지의 구조를 분석하고 구현 범위를 조정하는 과정이 중요하다는 점을 배웠습니다.

특히 공식 페이지의 모든 기능을 무리하게 따라 하기보다, 현재 프로젝트 목적과 기술 범위 안에서 설명 가능한 기능을 선별하는 데 집중했습니다.

중점적으로 다룬 부분은 다음과 같습니다.

- 첫 화면의 인상과 정보 흐름
- 헤더 패널처럼 상태가 많은 화면의 안정성
- 모바일과 데스크탑의 다른 탐색 흐름
- 키보드 접근성과 포커스 흐름
- 스타일 구조 분리와 문서화 기준
- 인공지능을 활용한 구현 방향 검토와 검수 범위 확장
- 배포 전 검수와 브랜치 기반 관리 흐름

<br />

## 한 줄 요약

Apple iPad 제품 페이지를 참고해 정적 퍼블리싱 기반으로 재구성한 개인 프론트엔드 리빌드 프로젝트입니다.

화면 복제보다 정보 구조, 상호작용 구현, 접근성 보완, 스타일 구조 정리, 인공지능 활용, 배포 전 검수 문서화에 초점을 두고 작업했습니다.
