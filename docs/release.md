# 릴리즈 배포 전 준비 사항

## 작업 브랜치
`feat/portfolio-polish`

## 대상 프로젝트
`iPad 11` 프로젝트

## 작업 목적
이번 작업은 `iPad 11` 프로젝트를 단순한 UI 클론 결과물에서, 포트폴리오용 리뉴얼 프로젝트로 다시 정리하기 위한 작업이다.

이 프로젝트는 처음부터 실무형 완성 프로젝트로 시작한 것이 아니라, 공홈 기반의 정적 학습용 UI 구현 프로젝트에서 출발했다.  
따라서 이번 브랜치의 목적은 Apple 공홈을 그대로 복제하는 것이 아니라, 기존 프로젝트의 한계를 분석하고 현재 시점에서 설명 가능한 구조로 재정리하는 데 있다.

이번 작업에서는 아래 내용을 문서와 코드에 함께 반영한다.

- 기존 학습형 프로젝트의 문제점
- Apple 공홈과 현재 프로젝트의 차이
- 현재 리뉴얼 과정에서 유지할 부분과 덜어낼 부분
- iPad 구매를 고려하는 사용자에게 어떤 흐름으로 정보를 전달할지
- 접근성, 마크업 역할, 반응형 기준을 왜 지금 구조로 선택했는지

즉 이 브랜치는 단순히 화면을 더 비슷하게 만드는 작업이 아니라,  
기존 클론 프로젝트를 현재 수준에서 설명 가능한 포트폴리오 프로젝트로 바꾸는 정리 작업이다.

---

## 프로젝트 리뉴얼 방향

### 기존 프로젝트의 출발점
기존 `iPad 11` 프로젝트는 Apple 공홈을 기반으로 한 UI 구현 학습용 프로젝트였다.

HTML, CSS, JavaScript로 구조와 시각 효과, 일부 인터랙션을 구현하는 데 초점이 있었고,  
전체 구조도 공홈을 참고한 시각 재현 중심 성격이 강했다.

### 기존 프로젝트의 문제점
- 단순 UI 구현 중심이라 프로젝트의 개선 의도가 문서로 정리되어 있지 않다.
- 헤더 이후 섹션의 콘텐츠 목적과 사용자 흐름이 충분히 설명되지 않는다.
- 실제 iPad 구매를 고려하는 사용자가 어떤 정보를 어떤 순서로 보게 되는지 설계 근거가 부족하다.
- 기존 마크업이 공홈 링크를 많이 포함하고 있어 프로젝트 자체의 맥락이 약해 보일 수 있다.
- 링크와 버튼의 역할이 혼재되면 접근성과 탐색 흐름이 어색해질 수 있다.
- 결과적으로 단순 클론처럼 보일 위험이 있다.

### Apple 공홈과의 차이 정리
Apple 공홈은 시각 완성도와 인터랙션 밀도가 매우 높은 브랜드 랜딩 페이지다.

하지만 이 프로젝트는 공홈을 그대로 재현하는 것이 목적이 아니라,

- 공홈의 시각 흐름과 정보 구조는 참고하되
- 현재 프로젝트 수준에서 유지보수 가능한 방식으로 정리하고
- 사용자 탐색 흐름과 접근성을 더 설명 가능한 구조로 바꾸는 것

에 목적이 있다.

특히 스크롤 기반 헤더 접근성, 모바일 패널 포커스 제어, 링크/버튼 정책 정리, CSS 구조 분리는  
단순 시각 재현보다 실제 사용성과 설명 가능성을 높이기 위한 리뉴얼 포인트로 본다.

### 리뉴얼 프로젝트의 방향
이번 리뉴얼은 “원본처럼 보이는 결과물”보다 “왜 이렇게 고쳤는지 설명할 수 있는 결과물”을 목표로 한다.

- 의미 있는 마크업
- 링크와 버튼 역할 구분
- 키보드 탐색 흐름
- 모바일 패널 포커스 제어
- 접근성 상태 관리
- 반응형 인터랙션 기준
- 불필요한 구조 제거
- CSS 역할 분리와 유지보수성 개선

이 기준을 중심으로 포트폴리오용 품질로 정리한다.

### 작업 내용
- README 및 관련 문서의 소개 문구 정리
- Apple 공홈 UI 클론처럼 보이는 인상 줄이기
- `iPad` 상품 소개 페이지를 모티브로 한 인터랙션 리뉴얼 프로젝트로 방향 정리
- 기존 프로젝트의 문제점 작성

## 2. 마크업 정책 반영

### 작업 목적
프로젝트 안에서 링크와 버튼의 역할을 명확히 구분하고, 접근성과 탐색 흐름 기준에 맞는 마크업으로 정리한다.

### 연결 문서
- [링크 / 버튼 마크업 정책](./link-button-policy.md)

### 우선 적용 범위
1. 헤더
2. 제품 내비게이션
3. 본문 섹션 CTA 및 인터랙션 요소
4. 푸터 링크 및 기존 링크 구조

### 작업 내용
- 실제 페이지 이동이 필요한 경우에만 `<a>` 사용
- 현재 페이지 안의 상태를 제어하는 경우 `<button>` 사용
- `href="#"`, `javascript:void(0)`, 클릭 가능한 `div` / `span` 패턴 제거
- 헤더와 푸터에 남아 있던 불필요한 외부 이동 링크 정리 또는 역할 구분
- 현재 페이지 컨텍스트에 맞지 않는 링크의 유지 여부를 다시 판단
- 본문 CTA를 `내부 이동`, `추가 정보 이동`, `구매/전환 CTA`로 분류
- 실제 구현하지 않은 기능은 억지로 링크로 만들지 않고 계획 상태로 구분

### 확인 기준
- 링크와 버튼의 역할이 명확하다.
- 의미 없는 가짜 링크가 남아 있지 않다.
- 헤더, 본문, 푸터의 탐색 흐름이 자연스럽다.

### 예상 커밋
```bash
refactor: 마크업 정책 기준으로 링크와 버튼 역할 정리
```

## 4. 반응형 디테일 점검

### 작업 목적
모바일, 태블릿, 데스크톱 주요 구간에서 레이아웃과 인터랙션 디테일을 다시 확인한다.

### 작업 내용
- hero / sticky / scroll interaction 구간 점검
- 스크롤 방향 기반 헤더 노출 흐름 점검
- 작은 화면에서 버튼 간격, 정렬, 터치 영역 점검
- 본문 CTA 흐름 점검
- hover / focus / active 상태 점검
- reduced motion 환경 점검
- 가로 스크롤 발생 여부 점검
- CSS 파일 분리 이후 cascade 영향 점검

### 확인 기준
- 주요 구간에서 레이아웃이 깨지지 않는다.
- 헤더와 패널 인터랙션이 자연스럽게 동작한다.
- 모바일과 데스크톱 모두에서 탐색 흐름이 자연스럽다.

### 예상 커밋

## 6. CSS 구조 마감 정리

### 작업 목적
기존 레이아웃과 인터랙션을 깨지 않고 CSS 역할 분리와 변수 체계를 정리해 유지보수성을 높인다.

### 작업 내용
- `styles/main.css`, `styles/header.css`, `styles/footer.css` 역할 분리
- 디자인 섹션은 `main.css`에 유지
- header / product-nav / footer 관련 cascade 정리
- 변수 이름 단순화 및 alias 유지
- 인코딩 및 깨진 주석 점검

### 확인 기준
- header / mobile panel / design / detail section 동작이 유지된다.
- HTML에서 CSS 로드 순서가 안정적이다.
- 실제 파일 인코딩 손상이 없다.

### 예상 커밋
```bash
refactor(css): 파일 역할 분리와 변수 체계 정리
```
