# 404 구조 분리, 반응형 정리, JS 모듈 분리

> **작업 일자:** 2026-05-08  
> **작업 브랜치:** `chore/ipad-final-polish`  
> **관련 커밋:** `ad335f2`, `d41ae4e`, `46444ef`, `466e9a4`

---

## 작업 개요

이 날 작업은 프로젝트를 실제 유지보수 가능한 형태로 다듬는 구조 정리에 가까웠다.

핵심 흐름은 아래와 같았다.

- 404 전용 본문 구조와 스타일 분리
- 루트 페이지 반응형 레이아웃 재정리
- 본문 compact 구간 반응형 보정
- 대형 `js/main.js`를 섹션별 모듈 구조로 분리

---

## 커밋 기준 작업 내역

### 1. `ad335f2`
`refactor(404): 404 전용 본문 구조 분리 및 전역 메뉴 렌더링 정리`

#### 주요 작업 내용
- `404.html` 전용 본문 구조를 정리하고, 루트 페이지와 404 페이지의 역할을 더 분리했다.
- `errors/404.css`를 새로 만들며 404 전용 스타일 파일을 분리했다.
- `main.css`를 `styles/main.css`로 이동하고, `reset.css`도 `styles/reset.css`로 정리했다.
- 전역 메뉴 렌더링과 관련된 JS 흐름을 다시 정리했다.

### 2. `d41ae4e`
`refactor: 404 전용 스타일 분리 및 루트 페이지 반응형 레이아웃 정리`

#### 주요 작업 내용
- 404 전용 스타일 분리 이후 루트 페이지의 반응형 레이아웃을 크게 재정리했다.
- `styles/reset.css`를 제거하고 스타일 구조를 단순화했다.
- `index.html`과 `styles/main.css`를 중심으로 루트 페이지 레이아웃을 다시 배열했다.

### 3. `46444ef`
`style(index.html): 본문 섹션 compact 반응형 보정`

- CSS만으로 해결 가능한 본문 spacing 및 정렬 문제를 정리했다.

### 4. `466e9a4`
`refactor(js): 본문 섹션별 JS 모듈 구조로 분리`

#### 주요 작업 내용
- 거대한 `js/main.js`를 기능 단위 모듈로 분리했다.
- `js/common/config.js`, `js/common/dom.js`를 만들고 공통 설정과 유틸을 분리했다.

- `js/README.md`를 추가해 JS 구조를 설명할 수 있게 했다.

## 작업 결과

- 404 페이지가 메인 페이지와 섞이지 않는 별도 구조로 정리되었다.
- CSS/HTML/JS 모두 파일 구조가 더 읽기 쉬운 방향으로 바뀌었다.
- JS는 기능별 책임이 분리되면서 이후 디버깅과 수정 진입 비용이 크게 줄었다.
- 루트 페이지 반응형 레이아웃도 이전보다 유지보수 관점에서 다루기 쉬워졌다.

---

## 인사이트 및 회고

- 기능을 추가하는 작업보다, 이미 커진 파일을 안전하게 분리하는 작업이 더 많은 주의가 필요했다.
- 404 페이지처럼 성격이 다른 화면은 초기에 구조를 분리해두는 편이 장기적으로 훨씬 안전하다.
- JS 모듈 분리는 단순 파일 쪼개기가 아니라, 공통 책임과 섹션 책임을 어디까지 나눌지 결정하는 설계 작업이었다.
