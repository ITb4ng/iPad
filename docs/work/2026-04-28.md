# 모바일 헤더 포커스 흐름 및 검색 UI 정리

> **작업 일자:** 2026-04-28  
> **작업 브랜치:** `feat/mobile-header-focus-trap`  
> **작업 범위:** 모바일 헤더 패널 접근성, 데스크탑 헤더 키보드 포커스 흐름, 검색 필드 UI 정리
> [Live Preview](https://ipad102-mrgbwqgy3-itb4ngs-projects.vercel.app/)

---

## 작업 개요

이번 작업은 모바일 헤더 패널의 접근성 흐름을 안정화하고, 데스크탑 헤더의 키보드 탐색 순서를 의도한 구조에 맞게 정리하는 데 초점을 두었다.  
기존 DOM 구조와 클래스 체계는 유지한 채, **포커스 이동 시점**, **패널 상태 동기화**, **검색 입력 필드와 보조 버튼의 시각적 분리**를 중심으로 수정했다.

---

## 주요 작업 내용

### 1. 모바일 헤더 패널 접근성 보강

* 모바일 검색 / 장바구니 / 전역메뉴 패널의 `aria-expanded`, `aria-hidden`, `aria-modal`, `inert` 상태가 실제 열림/닫힘 상태와 일치하도록 정리했다.
* 패널이 열린 동안에는 패널 외부 요소가 포커스 탐색에 잡히지 않도록 `inert`와 focus trap 흐름을 유지했다.
* 패널을 닫을 때는 기존 trigger 버튼으로 focus return이 되도록 흐름을 정리했다.

### 2. 모바일 패널 초기 포커스 흐름 정리

* 모바일 패널 오픈 직후 닫기 버튼(X)으로 포커스를 보내는 로직을 재정리했다.
* 단순히 오픈 함수 내부에서 바로 `focus()`를 호출하는 방식이 아니라, `syncInteractiveStates()`에서 모바일 flyout 상태가 실제로 확정된 뒤 최초 1회만 포커스를 예약하도록 바꿨다.
* `requestAnimationFrame`과 fallback 재시도 타이밍을 함께 사용해 렌더 반영 이후 닫기 버튼 포커스가 안정적으로 시도되게 했다.
* 디버그가 필요할 때만 상태를 확인할 수 있도록 `DEBUG` 기반 포커스 로그 함수를 추가했다.

### 3. 모바일 스크롤 락 문제 수정

* 전역메뉴를 닫은 뒤 `html.fixed`가 남아 스크롤이 풀리지 않던 문제를 수정했다.
* 닫힘 애니메이션 종료 시점에도 스크롤 락 상태를 다시 계산하도록 보강해, 메뉴가 닫힌 뒤 문서 스크롤이 정상 복구되게 했다.

### 4. 데스크탑 헤더 키보드 탐색 흐름 수정

* 데스크탑 검색 패널의 마지막 quick link에서 `Tab`을 누를 때, 다음 포커스가 product nav로 바로 넘어가던 흐름을 수정했다.
* 검색 패널 마지막 링크 이후 포커스 기준을 패널 내부 마지막 요소가 아니라 `basketStarterEl` 기준으로 바꿔, 장바구니 버튼으로 이동하게 했다.
* 장바구니 패널 마지막 링크 이후에도 같은 원칙을 적용해, 다음 포커스가 메뉴 trigger로 이동하도록 정리했다.

### 5. 검색 관련 JS/CSS 정리

* `js/main.js` 상단의 문법 오류와 인코딩 깨짐을 복구했다.
* 특히 `Unexpected identifier 'A16'`를 유발하던 문자열 깨짐과 비교 섹션 템플릿 문자열을 정상화해 스크립트 파싱이 다시 가능하도록 정리했다.
* 플라이아웃 관련 `console.log`는 `DEBUG`가 `false`일 때 절대 출력되지 않도록 정리했다.

### 6. 모바일 검색 필드 UI 개선

* 모바일 검색 리셋 버튼은 유니코드 `×` 대신 프로젝트 에셋 `header/header-close.svg`를 사용하도록 변경했다.
* 검색 리셋 버튼의 대비와 정렬을 조정해 데스크탑에서도 더 또렷하게 보이게 했다.
* 모바일에서는 검색 입력 필드의 실제 가로폭을 줄이고 가운데 정렬되게 조정해, 리셋 버튼과 패널 닫기 버튼이 서로 덜 헷갈리도록 개선했다.

## 트러블슈팅

### 1. 모바일 패널 포커스가 body에 머무는 문제

> 모바일 검색 패널이 열린 뒤 `document.activeElement`가 닫기 버튼이 아니라 `body`로 남아 있었다.  
> 확인 결과, `aria-hidden`, `aria-modal`, `inert` 상태 자체는 이미 정상 반영되고 있었고, 문제는 최종 열림 상태가 반영된 이후 포커스를 보장하는 시점에 있었다.

해결 방향은 오픈 함수 내부에서만 포커스를 시도하는 것이 아니라, 모바일 flyout 상태가 실제로 확정된 뒤 최초 1회만 포커스를 예약하도록 흐름을 바꾸는 것이었다.

### 2. 데스크탑 검색 패널 종료 후 포커스가 product nav로 넘어가는 문제

> 검색 패널 마지막 링크 기준으로 다음 focusable element를 찾으면, 닫힌 뒤에는 의도한 헤더 흐름이 아니라 product nav 쪽으로 건너뛸 수 있었다.

이 문제는 포커스 탐색 기준점을 패널 내부 링크가 아니라 헤더 trigger 자체로 바꾸는 방식으로 해결했다.

### 3. 검색 입력 필드와 닫기 버튼이 시각적으로 가까운 문제

> 모바일 검색 패널에서 입력 필드, 리셋 버튼, 패널 닫기 버튼이 모두 오른쪽에 몰려 보여 역할이 비슷하게 느껴졌다.

패딩만 조정하는 대신 검색 폼 자체의 폭을 줄이고 가운데 정렬하는 방식으로 해결해, 입력 영역과 패널 조작 영역이 시각적으로 더 분리되도록 했다.


## 인사이트 및 회고

* 모바일 접근성 이슈는 단순히 `focus()` 호출을 추가하는 것만으로 해결되지 않고, 상태 동기화가 완료되는 시점까지 함께 설계해야 한다.
* 헤더처럼 연속된 인터랙션이 많은 영역에서는 “다음 포커스 대상을 어디 기준으로 볼 것인가”가 키보드 UX를 크게 바꾼다.
* 리셋 버튼과 닫기 버튼처럼 역할이 가까운 요소는 아이콘 교체보다도 실제 필드 폭과 배치 구조를 조정하는 편이 더 직관적일 수 있다.
* 디버그 로그는 문제를 좁히는 데 도움이 되지만, 최종 코드에선 `DEBUG` 플래그 뒤로 숨겨 운영 환경과 분리하는 편이 안전하다.
