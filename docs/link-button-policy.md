# 링크 / 버튼 마크업 정책

> 대상 프로젝트: `iPad 11`  
> 목적: 프로젝트 안에서 `<a>`와 `<button>`의 역할을 명확히 구분하고,  
> 브랜드/상품 소개형 정적 사이트에 맞는 CTA 기준까지 함께 정리하기 위한 문서

---

## 1. 왜 이 문서가 필요한가

이 프로젝트는 단순한 정보 문서가 아니라,  
사용자가 상품 정보를 탐색하고 구매 관련 행동으로 이어질 수 있도록 구성된 브랜드 소개형 정적 사이트다.

이런 구조에서는 단순히 “예쁘게 보이는 링크”를 만드는 것보다 아래 기준이 더 중요하다.

- 이 요소가 실제로 이동을 일으키는가
- 현재 페이지 안의 UI 상태만 바꾸는가
- 정보 탐색용 CTA인가, 구매 유도 CTA인가
- 외부 Apple 공식 페이지로 보내는 것이 이 프로젝트 목적에 맞는가

따라서 이 문서는 단순 태그 선택 규칙이 아니라,  
**현재 프로젝트의 콘텐츠 목적과 사용자 흐름에 맞는 링크 정책**을 정리하는 데 목적이 있다.

---

## 2. 기본 원칙

### 링크 `<a>`
링크는 **사용자를 다른 위치로 이동시키는 요소**다.

아래에 해당하면 `<a>`를 사용한다.

- 다른 페이지로 이동
- 같은 페이지의 특정 섹션으로 이동
- 외부 사이트 또는 외부 상세 정보 페이지로 이동
- 전화, 메일, 지도처럼 목적지가 분명한 이동

### 버튼 `<button>`
버튼은 **현재 페이지 안에서 상태를 바꾸거나 UI를 제어하는 요소**다.

아래에 해당하면 `<button>`을 사용한다.

- 메뉴 열기 / 닫기
- 검색 패널 열기 / 닫기
- 장바구니 패널 열기 / 닫기
- 입력값 초기화
- 아코디언 열기 / 닫기
- 재생 / 일시정지

정리하면:

- 이동은 `<a>`
- 제어는 `<button>`

---

## 3. CTA 분류 기준

이 프로젝트는 상품 소개형 정적 사이트이므로, 링크도 목적에 따라 구분한다.

### 1차 CTA
사용자를 가장 중요한 행동으로 이끄는 링크다.

예:
- `구입하기`
- `iPad 쇼핑하기`
- `보상 판매 가격 알아보기`

기준:
- 실제 구매 또는 구매 직전 정보로 연결
- 본문 안에서 가장 강한 행동 유도
- 시각적으로도 우선순위가 높아야 함

### 2차 CTA
사용자가 더 많은 정보를 탐색하도록 돕는 링크다.

예:
- `더 알아보기`
- `비교하기`
- `AR로 보기`
- `셀룰러에 대해 더 알아보기`

기준:
- 구매보다 한 단계 앞선 탐색 목적
- 정보 보강 역할
- 같은 섹션 내에서 본문 설명과 연결되어야 함

### 탐색 링크
페이지의 구조적 이동을 담당하는 링크다.

예:
- 전역 헤더 메뉴
- 제품 내비게이션
- 브레드크럼
- 푸터 정책 링크

기준:
- 콘텐츠 소비보다 페이지 이동과 구조 인지에 목적이 있음

### 보조 링크
정책, 법적 고지, 전화, 계정, 주문 같은 보조 목적 링크다.

예:
- `개인정보 처리방침`
- `사이트 맵`
- `080-330-8877`
- `로그인`
- `주문`

## 4. 현재 프로젝트 적용 기준

### 헤더

링크로 유지:
- 전역 메뉴 항목
- 모바일 전역 메뉴 항목
- 검색 패널 quick link
- 장바구니 패널 안의 계정/주문/로그인 링크

버튼으로 유지:
- 검색 트리거
- 장바구니 트리거
- 전역메뉴 트리거
- 모바일 패널 닫기 버튼
- 검색어 초기화 버튼
- 검색 패널 취소 버튼

### 제품 내비게이션

링크로 유지:
- `개요`
- `제품 사양`
- `구입하기`

버튼으로 유지:
- 모바일 제품 메뉴 토글

### 본문 CTA

현재 프로젝트의 본문 CTA는 아래처럼 분류한다.

#### 내부 이동 링크
- `AR로 iPad 보기`
- `더 알아보기`(`#how-to-shop`)
- `더 알아보기`(`#trade`)
- 각주 링크(`#footnote...`)

이 링크들은 현재 페이지 안에서 콘텐츠 흐름을 이어 주므로 유지한다.

#### 외부 정보 링크
- `Apple Pencil에 대해 더 알아보기`
- `iPadOS의 다양한 기능 더 알아보기`
- `Apple과 환경에 대해 더 알아보기`
- `App Store에서 앱 찾아보기`
- `모든 손쉬운 사용 기능 더 알아보기`

이 링크들은 현재 프로젝트 안에서 모든 세부 정보를 직접 제공하지 않기 때문에,  
보조 정보 이동용 외부 링크로 유지 가능하다.

#### 구매/전환 링크
- `iPad 11 구입하기`
- `iPad 쇼핑하기`
- `보상 판매 가격 알아보기`
- `iPad 액세서리 쇼핑하기`

이 링크들은 상품 전환 목적이 명확하므로 1차 CTA로 유지한다.

### 푸터

링크로 유지:
- 브레드크럼
- 푸터 내비게이션 링크
- 정책/약관 링크
- 전화번호 `tel:` 링크

버튼으로 유지:
- 모바일 푸터 아코디언 토글

## 5. 외부 Apple 링크 유지 기준

이 프로젝트는 공홈 기반 리뉴얼 프로젝트이기 때문에 외부 Apple 링크를 무조건 제거할 필요는 없다.  
하지만 아래 기준으로 판단한다.

### 유지하는 경우
- 실제 상품/정책/지원 정보 목적지가 명확할 때
- 현재 프로젝트 내부에 같은 내용을 충분히 제공하지 않을 때
- 구매, 비교, 지원, 계정처럼 사용자 기대가 분명할 때

### 줄이거나 대체를 검토하는 경우
- 단순히 “공홈 같아 보이기 위해” 넣은 링크일 때
- 프로젝트 내부 흐름보다 외부 이탈을 먼저 유도할 때
- 의미가 겹치는 CTA가 과도하게 많을 때

### 대체 가능 방식
- 프로젝트 내부 섹션 이동으로 전환
- 문서/설명용 placeholder가 아니라 실제 제공 가능한 섹션으로 연결
- 현재 페이지에 이미 있는 내용을 다시 외부로 보내는 중복 링크는 축소

---

## 6. 금지 패턴

### 금지 1. `href="#"`로 버튼 역할 흉내내기

```html
<a href="#" class="menu-toggle">메뉴</a>
```

이유:
- 실제 이동 목적지가 없다.
- 링크와 버튼 역할이 섞인다.

### 금지 2. `javascript:void(0)` 링크

```html
<a href="javascript:void(0)">닫기</a>
```

이유:
- 역할이 불분명하다.
- 유지보수와 접근성 모두 불리하다.

### 금지 3. 클릭 가능한 `div`, `span`

```html
<div class="search-trigger"></div>
```

이유:
- 기본 키보드 접근성이 없다.
- 버튼 의미가 필요한 자리에 맞지 않는다.

---

## 7. 접근성 보조 규칙

### 링크
- 현재 위치를 나타낼 때만 `aria-current="page"` 사용
- 같은 페이지 섹션 이동 링크는 실제 연결 대상 id가 존재해야 함
- 전화번호는 `tel:` 링크 사용

### 버튼
- 열고 닫는 버튼은 실제 상태에 맞게 `aria-expanded` 갱신
- 제어 대상이 있으면 `aria-controls` 연결
- 패널/다이얼로그 성격이면 필요에 따라 `aria-haspopup`, `aria-modal` 사용

## 9. 현재 반영 상태를 볼 때 다음 점검 대상

현재 프로젝트는 헤더, 제품 내비게이션, 푸터 기준으로는 정책 반영이 많이 진행된 상태다.  
다음 점검 대상은 본문 CTA다.

우선순위:
1. 본문 CTA를 내부 이동 / 외부 정보 / 구매 CTA로 분류
2. 외부 Apple 링크 중 과한 중복이 있는지 확인
3. 현재 프로젝트 안에서 소화 가능한 링크는 내부 흐름으로 대체 검토

## 10. 결론

현재 프로젝트 기준 핵심 원칙은 아래 두 줄로 정리된다.

- **이동은 링크**
- **제어는 버튼**

다만 포트폴리오형 리뉴얼 프로젝트에서는 여기서 한 단계 더 나아가,  
**이 링크가 왜 필요한지, 어떤 사용자 흐름에 속하는지**까지 같이 판단해야 한다.

즉 이 문서는 단순 태그 규칙 문서가 아니라,  
브랜드/상품 소개형 정적 사이트에 맞는 탐색 구조와 CTA 정책 문서로 사용한다.
