오늘 작업은 배포 직전 마감 보정에 가까운 후속 정리 작업으로 진행했다.

- JS 모듈 import 경로 오류 수정

## 오늘 작업 내용

### 1. CSS 파일 구조 분리

- 기존 `styles/main.css`에 길게 이어져 있던 header / product-nav / footer 스타일을 파일 단위로 분리했다.
- 새 파일:
  - `styles/header.css`
  - `styles/footer.css`
- `styles/main.css`는 공통 스타일, 본문 섹션, 디자인 섹션, detail 섹션, commerce 섹션, responsive override, reduced motion, keyframes 중심으로 정리했다.
- 디자인 섹션 전용 CSS는 요청 기준에 따라 `main.css`에 그대로 유지했다.
- `index.html`, `404.html`에서 CSS 로드 순서를 `main.css → header.css → footer.css`로 맞췄다.

### 2. CSS 변수 체계 정리

- 반복적으로 쓰이던 전역 값을 더 짧고 읽기 쉬운 이름으로 정리했다.
- 예:
  - `--header-h`
  - `--panel-h`
  - `--nav-h`
  - `--page-w`
  - `--page-pad`
  - `--text`
  - `--accent`
  - `--line`
  - `--surface-section`
- 기존 변수명은 바로 제거하지 않고 alias로 남겨, 아직 옮기지 않은 규칙과 JS 연결에 영향이 없도록 했다.
- 실제 선언부에서는 새 변수명을 우선 사용하도록 정리했다.

### 3. 디자인 섹션 구조 정리

- 디자인 섹션은 별도 파일로 빼지 않고 `main.css` 내부에서 유지했다.
- `snipe`, `badge`, `video shell`, `swap mode` 관련 구조에 설명 주석을 보강해 읽기 쉽게 정리했다.
- 위치값 자체는 민감하므로 시각 보정값은 바꾸지 않고, 공통 패턴과 설명만 정리했다.

### 4. 무효 주석 / 인코딩 점검

- 프로젝트 파일 전체를 기준으로 실제 인코딩 깨짐이 있는지 점검했다.
- 확인 결과:
  - 실제 UTF-8 파일 손상은 발견되지 않았다.
  - PowerShell 출력에서만 깨져 보이는 문자열이 있었고, 브라우저 기준 원문은 정상임을 확인했다.
- `footer.css`의 읽기 어려운 주석과 이중 세미콜론 같은 사소한 찌꺼기를 정리했다.
- CSS 주석 블록 개수도 파일별로 맞는지 확인했다.

### 5. JS import 경로 수정

- 라이브 서버에서 JS가 로드되지 않던 원인을 확인했다.
- 기존 모듈들이 `shared` 경로를 import하고 있었지만 실제 구조는 `common`이었기 때문에 관련 import 경로를 실제 디렉터리 구조에 맞게 수정했다.
- 수정 대상:
  - `js/main.js`
  - `js/modules/compare.js`
  - `js/modules/error-page.js`
  - `js/modules/footer.js`
  - `js/modules/global-navigation.js`
  - `js/modules/header-navigation.js`
  - `js/modules/hero.js`
  - `js/modules/videos.js`

### 6. compare 하단 링크 정렬 보정

- compare 섹션 하단의 두 링크가 가운데에 몰려 보이던 부분을 정리했다.
- `flex` 기준으로 두 링크가 같은 영역을 나눠 갖도록 보정했다.
- 모바일에서는 기존 의도대로 1열로 떨어지도록 유지했다.

### 7. 문서 최신화

- `docs/css-refactor-qa.md`를 최신 리팩토링 상태 기준으로 갱신했다.

## 확인 결과

- CSS는 이제 파일 역할이 더 명확해졌다.
  - `main.css`: 공통 + 본문 + 디자인 + detail
  - `header.css`: header + product-nav + 관련 상태 클래스
  - `footer.css`: footer + footer responsive
- 실제 파일 인코딩 손상은 발견되지 않았다.
- JS import 경로 문제는 수정 완료 상태다.
- 디자인 섹션은 분리하지 않고 `main.css`에 남겨 요청 기준을 유지했다.
- 브라우저 시각 회귀 테스트는 아직 남아 있다.

---

## 인사이트 및 회고

- 후반부 리팩토링은 “더 많이 나누는 것”보다 “어디까지 나눠도 안전한가”를 판단하는 작업에 가깝다.
- header와 product-nav는 JS 상태 클래스와 강하게 연결되어 있어, 파일 분리는 가능해도 동작 단순화는 매우 보수적으로 다뤄야 한다.
- 디자인 섹션은 별도 파일로 분리하는 것보다 현재 단계에서는 `main.css` 안에 두고 설명과 토큰만 정리하는 편이 더 안전했다.
- 인코딩 문제처럼 보이는 현상도 실제 파일 손상인지 터미널 표시 문제인지 먼저 분리해서 확인해야 불필요한 수정이 줄어든다.
